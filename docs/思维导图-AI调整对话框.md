# 导图页 · 「不满意就让 AI 改」对话框

> 面向使用者的一页说明：在**思维导图**页右下角有一个常驻浮标「不满意？让 AI 改」。点开后用大白话说哪里不满意，AI 会把这句话翻译成一组**可执行的结构编辑**，你确认后才真正落到导图上，并且随时能撤回。

## 1. 它解决什么

AI 一次性生成 100+ 节点，几乎不可能一遍就合心意。以前只能去改 YAML 或者整包重新生成；现在可以像跟同事提意见一样：

- 「机器学习这块太笼统了，帮我拆细」
- 「『知识表示与推理』这个名字不准确，改掉」
- 「删掉跟主题无关的节点」
- 「把『词向量』挪到『计算机视觉』下面」

## 2. 交互流程（三步）

| 步骤 | 你看到的 | 底层做什么 |
|---|---|---|
| ① 说 | 右下角浮标 → 对话框；可点快捷句式，也可自由输入（Enter 发送 / Shift+Enter 换行） | 把当前知识树压成「id :: 名称 [层级]｜定义」清单（L4 只报数量），连同你的话和**当前选中节点**一起给模型 |
| ② 确认 | 气泡里出现「待确认：新增 3 · 改名 1」+ 逐条带勾选框的改动清单，可点「全选 / 全不选」，勾选数实时反映在按钮上（「应用选中的 2 条」） | 模型只输出 JSON 编辑计划；系统逐条校验 id / 父节点 / 数值范围，非法项丢弃；每条再单独试跑一次，改不动的（同名改名、移到自己子树、删根节点）标红并自动取消勾选 |
| ③ 应用 | 点「应用全部」或「应用选中的 N 条」→ 导图立即重绘、自动展开落点分支、底部提示「已应用」 | 纯函数把**勾中的那几条**落到 Project → 写入 store → 序列化回该项目的 5 个 YAML |

不满意这一版就点「忽略」，导图不动。应用后底部会显示「可撤回 N 步 · 最近：…」，**最多保留最近 5 步**，可以连着往回退；同一版清单重复点击只生效一次（防手抖连点）。

## 3. 支持哪几类修改

| 操作 | 说明 | 例子 |
|---|---|---|
| `add` 新增 | 挂在指定父节点下，层级自动取「父级 +1」，继承分支色与维度 | 「在『线性回归』下加一个『正则化』」 |
| `rename` 改名 | 改中文名/英文名；L3 改名时其下「X·输入识别」等 L4 前缀同步改 | 「把『自动推理』改名为『自动推理与规划』」 |
| `update` 修改 | 定义、描述、难度（1–4）、重要度（0–100）、建议时长、标签 | 「这个节点定义太虚，写具体点」 |
| `move` 移动 | 换父节点，整棵子树跟着走，并按新深度重算层级、跟着新分支换色 | 「把『词向量』移到『计算机视觉』下」 |
| `remove` 删除 | 连子节点一起删；前导依赖、路线引用同步清理 | 「删掉『本体论』这一支」 |

安全边界：**根节点不可删**；L4 下面不能再加子节点；一次最多 24 个操作；只做你明确说的事，不顺手大改。

## 4. 模型慢/不可用时会怎样

- 明确的短指令（改名 / 删除 / 新增 / 移动 / 拆细 / 精简）走**本地规则**，0.1 秒出结果，标记「本地规则」，不联网也能用。
- 模糊的诉求（「这块太杂了，帮我重构一下」）才调模型；等待超过 12 秒会显示已等待秒数，超过 25 秒提示可以改用明确说法。
- 模型超时/报错时，如果能用本地规则兜住就直接兜；兜不住会给出错误提示 + 四种可用的明确句式。

## 5. 和「重新生成」的分工

| 场景 | 用什么 |
|---|---|
| 大方向不对、分支划分完全不合理 | 项目设置 → 重新生成（整包重跑） |
| 局部名字、层级、增删、措辞 | 本对话框（只动你点名的部分，其余节点保持原样） |
| 想手工精修 | 节点详情面板（定义/描述/学习内容）或直接改 YAML |

## 6. 落地位置（给维护者）

| 文件 | 职责 |
|---|---|
| `src/components/MapAdjustPanel.tsx` | 浮标 + 对话框 UI、消息流、逐条勾选、应用/忽略/多级撤回 |
| `src/lib/adjust.ts` | 提示词组装、模型输出解析与校验、编辑计划应用（纯函数）、本地规则兜底 |
| `src/views/MindMapView.tsx` | 挂载 `.mm-ai-dock`（阻止画布拖拽/滚轮穿透）、应用后展开落点并重新适应窗口 |
| `src/styles/app.css` | `.mm-ai-*` 全套样式（与既有设计令牌一致） |
| `scripts/verify-adjust.mjs` / `scripts/shoot-adjust.mjs` | 网页态端到端冒烟：打开面板 → 出清单 → 逐条勾选 → 部分应用 → 校验 store/YAML → 多级撤回 |
| `scripts/verify-electron-ai.mjs` / `scripts/verify-electron-gen.mjs` | 桌面态（Electron + 真模型）验证：模糊指令出计划、应用生效、生成全新知识体系 |

数据结构不变：仍然是 `Project.nodes / edges / routes`，应用后照常通过 `serializeProject()` 写回 5 个 YAML，因此导入导出、四视图、Obsidian 导出都自动复用。

## 7. 当前验证结果

内置模型：OpenAI 兼容网关（地址与 key 见本地配置）· `deepseek-v4-flash`。

| 检查 | 结果 |
|---|---|
| `tsc -b --noEmit` / `vite build` | 通过 |
| 桌面端真模型 · 模糊指令 | 14.2s 返回「新增 3 · 改名 1」，4 条改动全部合法且准确，应用后节点 172→175 |
| 桌面端真模型 · 明确指令 | 「把 A 改名为 B」走本地规则，0.0s 出结果并生效；重复执行时正确提示「新名称与原来相同（未生效）」 |
| 桌面端真模型 · 新建生成 | 95s 完成「联网检索 → 骨架 → 大纲 → 组装 → 校验」，产出 153 节点 / 152 边 / 8 分支 / 96 个 L4 / 3 条路线 |
| 网页态 `verify-adjust.mjs` | ALL PASS：6 条清单 → 只勾 2 条 → 169→171（正好 +2）→ 自动展开 → 「可撤回 2 步」→ 连撤两次回到 169 |
| 纯函数单测 | PASS：边界操作（同名改名 / 移入自身子树 / 删根）判为未生效；部分应用只落选中项；空选择不改数据；入参不被修改 |

### 接这个代理时必须知道的两件事

1. **它会静默丢弃 `system` 消息**。实测同一提示词放 system 时 `prompt_tokens` 恒为 64、内容完全不生效，放 user 时正常（805）。`llm.ts` 因此默认开启 `mergeSystemIntoUser`，把系统指令折叠进首条 user 消息；换到正常接口时设为 `false` 即可。
2. **它不保证输出 YAML 顶层键**。生成链路里模型有时直接给 `id: / name: / branches:`，省掉 `domain:` 包装。已在两处加固：提示词显式要求首行写顶层键；解析器按内容特征认领三块并补回包装，避免白白多等一轮重试。
