# 联网调研能力（TavilyMux）接入说明

> 本文件记录 knowledge-viz 内置的联网能力：从哪来、怎么用、为什么这么设计。
> 所有参数均为**本机实测**，不是照抄文档。

## 二、七个产品化用法（都走联网）

### 1. 深入研究（ResearchPage → 深入研究）

一次填多个问题，全部并发。每个结论附来源链接。

- 默认 `model=mini`（实测 13–23s/条）
- pro 档实测 **160s+**，只在后台跑，不放交互链路
- 来源为空时自动补一次 search 兜底（网关 research 有相当比例不回 sources，但结论两三千字，没来源不可核验）

### 2. 事实核查（ResearchPage → 事实核查）

多条说法 × 每条 N 票，两层都并发。

**置信度是票型后验，不是模型自报值。** 这是本次最重要的实测结论：

| 项 | 实测 |
| --- | --- |
| 模型自报 confidence | 答对答错都是 **0.90–0.99**（7 条基准题全对时全是 0.99；错判时也是 0.90–0.97）→ **无区分度** |
| 采用公式 | `confidence = (k+1)/(n+2) × (0.9 + 0.1 × 有信源比例)` |
| 3/3 全一致 | **0.80** |
| 4/5 | 0.714 |
| 2/3 | 0.60 |
| 1/2 | 0.50 |
| 3/5 | 0.571 |

页面上仍显示「自报 0.99」作对照，让用户看见差异。

**必须多票 + 多角度**：
- 同一问法重复 5 次 → 44.6s，5/5 假一致
- 换 5 种角度 → 23s，暴露 4:1 分歧
- 边界说法 3 票会抖（2:1），5 票才稳定（4:1）→ 重要结论用 5 票

### 3. 节点资源联网补全（节点详情 → 资源）

3 个角度并发检索（定义/原理、教程/实践、进阶/对比），合并去重后**按域名可信度加权排序**：

| 域名类型 | 权重 | 例子 |
| --- | --- | --- |
| 学术 | 10 | arxiv / acm / ieee / nature |
| 官方文档 | 10 | github / MDN / python docs |
| 百科 | 9 | wikipedia |
| 高校 | 9 | .edu / .edu.cn |
| 慕课 | 8 | coursera / 中国大学MOOC |
| 技术社区 | 5 | 知乎 / 掘金 / CSDN |
| 内容农场 | **1** | 搜狐 / 163 / kuku.baidu / 百家号 |

实测效果：8 条资料得分 `[99,98,97,97,97,95,93,87]`，内容农场被压到最底。

### 4. 联网扩展子节点（节点详情 → 关联）★ 接入思维导图的关键

选中任意知识点 → 联网调研 → 生成 8 个下级概念（带一句话定义 + 来源）→ 勾选 → **直接并入思维导图 / 图谱 / 学习路线**。

实测：53s 出 8 个候选，全部带定义，并入后树节点 21 → 29。

**踩过的坑**：v1 用「搜结果标题切词」抽候选，中文标题多为问句式（「什么是知识图谱？有哪些典型应用？」），切出来全是噪声，**0 个有效候选**。改成让 research 按 JSON schema 直接产出候选才稳定。

### 5. 生成时以联网资料为依据（创建页）

`generate.ts` 在骨架调用前先并发 3 个查询检索领域资料，把命中标题塞进 skeleton / outline 的 prompt：

> 「8 个分支请优先复用这些标题里出现的术语（不要自造）」

联网失败不影响主链路（自动回退纯模型生成）。`GenerateResult.webEvidence` 带回检索依据，便于事后核对这份体系基于什么资料。

### 6. AI 重排学习路线（学习路线视图）★

`ai-route.ts` + `RouteView` 工具栏的「AI 重排路线」按钮。

原来本地生成的学习路线是按「L1→L2→L3→L4 + 分支顺序」机械分段的，分支之间的先后并不是真的按「先学什么」排的。这个功能：

1. 并发 3 个查询找该领域的**主流学习路径 / 课程大纲 / 新手误区**做校准
2. 一次 research（带 schema）产出 3–4 个阶段 + 每阶段排序理由
3. **严格校验**：只接受真实存在的节点 id；模型漏掉的节点按层级补到末阶段；B 依赖 A 但 B 在前时，把 A 提到 B 的阶段
4. 保存为**新路线**，不覆盖原路线

支持 4 档难度：零基础 / 有基础 / 系统学 / 进阶专家。实测 39s，3 阶段 20 节点，带 5–6 个联网来源。

**兜底设计**：research 报错 / 超时 / 网关 401 时，本地按「层级 + 拓扑排序」给出可用路线，并在描述里注明，用户不会空手而归（实测网关偶发 `account deactivated`，靠这层兜底 + 401 自动重试双重保障）。

### 7. 学习材料联网取证（节点详情 → 学习）

`learning.ts` 的 `aiLearning` 在调模型前先并发 3 个查询（教程/实操步骤、常见错误、最佳实践），把真实资料片段塞进 prompt，避免「名词解释 + 空话」。

## 三、并发模型

### 三层闸门

| 类型 | 并发上限 | 实测依据 |
| --- | --- | --- |
| search / extract | **16** | 32 路 advanced 搜索 4.3s，零失败 |
| research | **6**（Python 侧 8） | 8 路 17.8s 全成功；16 路出现 `no_available_key`；24+ 拖到 45s+ |
| 页面批量 | 不限（排队） | 外层开多少都行，真正限流在最内层闸门 |

### 为什么闸门必须在主进程

渲染进程多窗口 / 多次点击会各自算并发，叠加起来把上游打爆。主进程单例闸门才能全局生效。

### 批量任务的额外限流（踩过的坑）

IPC 层的批量接口**不能无限并发**：

| 接口 | 说法/任务并发 | 依据 |
| --- | --- | --- |
| `netResearchMany` | 4 | 每条还会补一次来源搜索 |
| `netJudgeMany` | 3（× 每条票数） | 10 条 × 3 票 = 30 路同时打，实测 **221s 零返回** |

限到 3×3=9 路后，2 条说法并发核查 **22s** 稳定返回。

### 典型耗时

| 操作 | 耗时 |
| --- | --- |
| 单条 search | 1–4s |
| 单条 research（mini） | 13–23s |
| 3 票 deep 核查 | 17–40s（并发，串行需 3×） |
| 2 条说法并发核查 | 17–22s |
| 8 个候选扩展 | 53s（1 次 research + 8 路并发补定义） |
| 节点资源补全 | 2–5s |
| AI 重排学习路线 | 39–45s（3 查询 + 1 research + 校验） |

## 五、坑位速查

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| research 不回 sources | 结论几千字但无来源 | `researchWithSources()` 自动补 search 兜底 |
| 模型自报置信度 | 恒 0.90–0.99，对错都高 | 改用票型后验（已内置） |
| 同问法重复采样 | 假一致，还慢一倍 | `ANGLES` 多角度（已内置） |
| 搜索结果标题切词 | 中文问句标题切出噪声 | 用 research + schema 出候选 |
| research 并发过高 | `no_available_key` | 闸门压到 6–8 |
| sources 是对象数组 | 前端 `new URL(obj)` 崩 | `{url,title,favicon}[]` → 拍平成字符串 |
| 页面重渲染时 CDP 超时 | 自动化偶发 timeout | 脚本重试，非应用问题 |
| 网关 401 `account deactivated` | 请求偶发全失败 | `request()` 内置 3 次指数退避重试；AI 路线另有本地兜底 |
| 保存路线后列表不变 | `upsertRoute` 用了 stale 闭包 | 改用 `setProjects` 函数式更新 |
